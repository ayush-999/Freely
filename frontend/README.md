# Freely Frontend

Freely is a governance platform focused on issue reporting and microblogging. This frontend repository is organized as a monorepo using Vite, TypeScript, and shared UI packages.

## Project Goals

- Issue reporting and tracking
- Community updates and microblogging
- Governance dashboard and administrative views
- Shared UI and reusable app architecture
- Scalable folder structure for growing features

## Tech Stack

- React 19
- TypeScript
- Vite
- React Router DOM
- Redux Toolkit
- React Query
- React Hook Form + Zod
- Axios
- date-fns
- Leaflet + React Leaflet
- Lucide React
- Tailwind-based shared UI package

## Folder and File Purpose

### Root Level

- `package.json` — root workspace configuration, scripts, and package manager details.
- `turbo.json` — Turbo repo pipeline setup for build/lint/typecheck orchestration.
- `tsconfig.json` — TypeScript project references for the monorepo.
- `package-lock.json` — lockfile generated by npm.
- `.npmrc` / `.gitignore` / `.prettierrc` — repository config for package resolution, git ignore rules, and formatting.

### apps/web

- `index.html` — app entry HTML file.
- `vite.config.ts` — Vite config and alias resolution.
- `eslint.config.js` — linting setup.
- `components.json` — configuration for shadcn/ui style patterns.
- `package.json` — frontend app dependencies and scripts.

### src/app

- `providers.tsx` — global providers such as Redux and theme context.
- `router.tsx` — top-level route definitions and lazy-loaded page imports.

### src/components

- `theme-provider.tsx` — theme toggling and app theming.
- `common/EmptyState.tsx` — reusable empty data display state.
- `common/RouteLoader.tsx` — loading spinner for lazy-loaded routes.
- `layout/AppShell.tsx` — shared page shell and overall app layout.

### src/hooks

- `useAppDispatch.ts` — typed Redux dispatch hook.
- `useAppSelector.ts` — typed Redux selector hook.
- `useDebounce.ts` — debounced value utility for search/filter behavior.
- `useLocalStorage.ts` — persistent local storage hook.
- `index.ts` — exports all hooks from one entry point.

### src/lib

- `utils.ts` — shared application utility functions such as `cn` helpers.

### src/pages

- `DashboardPage.tsx` — overview page for governance metrics and summaries.
- `IssuesPage.tsx` — issue reporting and listing screen.
- `PostsPage.tsx` — microblogging/community posts view.

### src/redux

- `store.ts` — central Redux store configuration.
- `slices/authSlice.ts` — authentication state and login/logout reducers.
- `slices/issuesSlice.ts` — issue-related application state.
- `slices/postsSlice.ts` — post-related state and feed updates.
- `slices/uiSlice.ts` — UI state like sidebar and search filters.

### src/routes

- `AppRoutes.tsx` — route definitions and navigation wiring.

### src/services

- `api.ts` — shared Axios instance with base URL and auth interceptor.
- `authService.ts` — login and current user API helpers.
- `issuesService.ts` — issue retrieval and creation requests.
- `postsService.ts` — post fetching and creation requests.

### src/types

- `auth.ts` — user and auth state type definitions.
- `common.ts` — shared types like loading states and pagination.
- `issue.ts` — issue models and status/priority enums.
- `post.ts` — post models and visibility typing.

### packages/ui

- Shared UI package used across apps.
- `src/components/button.tsx` — reusable button component managed from the UI package.
- `src/styles/globals.css` — common global CSS styles.
- `src/lib/utils.ts` — utility helpers used by shared components.

## Application Flow

1. The app boots from `apps/web/src/main.tsx`.
2. Global providers are applied through `src/app/providers.tsx`.
3. The app root renders the router from `src/app/router.tsx`.
4. Route-based pages are lazily loaded for better performance.
5. Redux manages auth, issues, posts, and UI state.
6. Service files interact with the backend through Axios.
7. Shared UI is consumed from the `packages/ui` package.

## Local Development

Install dependencies from the repo root:

```bash
npm install
```

Run the frontend app:

```bash
npm run dev
```

Or run the web app directly:

```bash
cd apps/web
npm run dev
```

## Build and Validation

To build the project:

```bash
npm run build
```

To type-check the app:

```bash
cd apps/web
npm run typecheck
```

## Notes

- The project is intentionally organized to support scalable feature growth.
- The web app structure already includes the core folders for hooks, routing, Redux, services, and types.
- New features can be added under `src/pages`, `src/services`, and `src/redux/slices` without changing the overall architecture.
